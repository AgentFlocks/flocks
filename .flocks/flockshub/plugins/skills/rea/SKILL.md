# REA 逆向分析

基于 Reverse Engineer Anything（npm 包 `rea-agents`，锁定 6.4.0）的逆向分析工具，帮助还原关键逻辑、算法或接口流程。分析在 Rex 会话里进行，材料和成果跟着会话走。

## 入口与状态

- Rex 新会话的「REA 逆向分析」快捷入口和插件广场共用一份插件状态：未安装、安装中、验证中、基础可用、安装失败、已安装异常、卸载中、卸载失败。
- 入口右上角的「新」只给还没完成首次安装的账号看，而且只在本次 Flocks 版本的引导期内显示；首次安装验证通过后永久去掉，卸载、重装都不恢复，Flocks 升级到下一个版本后也不再显示。
- 只有管理员能安装、修复和卸载；成员在 REA 基础可用后可以直接使用。

## 安装

- 点入口或插件广场的「安装」，会开一个 Rex 会话，把《REA 安装指引》作为第一条消息发出去。Rex 调用 `rea_analysis`（`action=install`）列出两个档位的安装方案，由用户选档位并确认后才安装：
  - 轻量档：JavaScript / .NET / 压缩包分析，不装 JDK 和 Ghidra。
  - 完整档：再装 JDK 21（`dnf install -y java-21-openjdk-devel`）和 Ghidra 12.1.4（经镜像下载、校验官方 SHA-256、解包到 `/opt`），用于反编译原生 ELF / PE。
- 已有的组件直接复用，缺的并行安装；MCP 服务 `rea`（`npx -y rea-agents@6.4.0 --mcp`）只注册一次，完整档写入 `GHIDRA_INSTALL_DIR` 和 `JAVA_HOME`。需要 root 或可写目录时，Rex 会给出具体命令，由用户执行后重试。
- 验证用本地生成的样例做真实工具调用：轻量档是 JavaScript、.NET、ZIP 三类，完整档再加一个 C 程序的 `open_binary` + `procedure_pseudo_code` 反编译。静态分析和运行核对分开记录；只看服务启动或工具数量（170）不算通过。轻量档通过不代表原生反编译可用。

## 分析

- 验证通过后，Rex 会询问要分析的文件、下载链接或网址，以及想解决的问题。REA 就绪后，样本可以直接在输入框附加（不限文件类型）。
- 按目标补齐专项工具，系统软件包或大型工具安装前先征得同意。优先用原程序或原运行环境核对结论；运行未知样本前先征得同意，尽量放在隔离环境里。

## 卸载

- 在插件广场卸载：停用 REA，移除 MCP 服务 `rea` 的配置、技能 `reverse-engineer-anything`、安装记录和验证样例；保留 JDK、`/opt/ghidra_*`、`/root/.npm/_npx` 缓存、历史会话、上传的材料和报告。
- 有正在使用 REA 的任务时，先说明会停止哪些任务，用户确认后才停止并卸载；失败会列出残留项，可以重试。

## 成果

- 用 `write` 把完整报告存进输出目录，再调用 `rea_analysis`（`action=report`）在会话里展示成果卡：简明结论、关键原理、可复核证据、验证情况、推断与未完成项。
