## 1. 功能目标

在 Rex 新会话中提供 REA 逆向分析快捷入口，通过会话完成首次安装与后续分析；同时支持在插件广场安装、卸载 REA 插件。两个入口复用同一份插件状态和配置。

用户无需先了解技能、工具服务及依赖之间的关系。首次使用先完成基础安装验证，再提供分析材料；后续使用复用已有配置，根据目标补齐专项工具。

## 2. 范围与需求边界

### 2.1 本期范围

- Rex 新会话中的「REA 逆向分析」小框入口。
- 首次点击将安装引导语填入输入框，由用户编辑并手动发送。
- 安装后点击将使用引导语填入输入框，由用户编辑并手动发送。
- 插件广场中的 REA 插件展示、安装与卸载。
- 安装状态同步、配置复用、基础可用性验证、失败排查与重试。
- 基础验证通过后收集目标与问题，并开展逆向分析和结果验证。

### 2.2 不作预先承诺

不以插件安装完成承诺所有文件类型、运行环境或专项分析能力均已验证。具体能力按目标检查工具、依赖和运行环境后确认。

## 3. 页面与入口

### 3.1 Rex 新会话

| 项目 | 要求 |
| --- | --- |
| 位置 | 与「告警运营」「威胁狩猎」「应急响应」同一行 |
| 形态 | 紧凑小框，与现有快捷入口保持一致 |
| 名称 | REA 逆向分析 |
| 图标 | 红色线性插头图标，按用户提供的参考样式 |
| 角标 | 右上角红底白字「新」；仅在未完成首次安装且仍处于本次版本引导期时显示 |
| 点击行为 | 按插件状态将对应引导语填入 Rex 输入框，不自动发送 |

快捷入口不增加独立安装表单。安装、配置检查、故障处理和分析引导在会话内完成。

### 3.2 插件广场

REA 插件条目至少展示插件名称、说明、当前状态及相应操作。

- 名称：REA 逆向分析。
- 说明：基于 Reverse Engineer Anything 的逆向分析工具，帮助还原关键逻辑、算法或接口流程。
- 未安装：展示「安装」。
- 安装中或验证中：展示进度，避免重复提交。
- 已安装且基础可用：展示「使用」「卸载」。
- 已安装但验证失败：展示异常说明及「排查并修复」「卸载」。
- 卸载中：展示进度，避免重复提交。

点击「安装」进入 Rex 输入界面并填入安装引导语，由用户手动发送后启动安装流程。点击「使用」填入使用引导语，由用户上传附件并手动发送后开始分析。插件广场直接提供卸载操作与结果反馈。

## 4. 状态与同步规则

会话入口和插件广场安装使用同一份统一插件状态，包括未安装、安装中、验证中、基础可用、安装失败、已安装异常、卸载中和卸载失败。任一入口发起的安装、验证、修复或卸载结果均更新这份状态，另一入口同步展示；不分别维护各自的安装状态。状态须以实际配置、安装任务和验证结果为依据，不仅依赖浏览器本地标记。

「新」角标独立于当前安装状态：仅对尚未完成首次安装、且本次版本引导期尚未结束的用户显示。首次安装完成后永久移除；卸载成功和再次安装均不恢复。一直未安装的用户，在下次 Flocks 版本更新后移除角标。

| 状态 | 判定 | 快捷入口角标 | 点击快捷入口 | 插件广场操作 |
| --- | --- | --- | --- | --- |
| 未安装 | 当前使用范围内未配置 REA 插件 | 按首次安装及版本规则显示 | 填入安装提示语（不自动发送） | 安装 |
| 安装中 | 安装或配置任务正在执行 | 按首次安装及版本规则显示 | 打开正在执行的安装会话 | 查看进度 |
| 验证中 | 基础组件已配置，正在验证可用性 | 按首次安装及版本规则显示 | 打开验证会话 | 查看进度 |
| 基础可用 | 服务启动、工具清单、真实工具调用均通过 | 无 | 填入使用提示语（不自动发送） | 使用、卸载 |
| 安装失败 | 安装或首次基础验证未通过 | 按首次安装及版本规则显示 | 继续排查、修复和验证 | 排查并修复、卸载已安装组件 |
| 已安装异常 | 曾通过基础验证，当前服务或配置不可用 | 无 | 进入分析会话，先检查并修复配置 | 排查并修复、卸载 |
| 卸载中 | 正在移除插件及其专属配置 | 保持卸载前状态 | 展示卸载进度，不启动分析 | 查看进度 |
| 卸载失败 | 插件或配置仅部分移除 | 按实际状态展示 | 说明异常并引导修复 | 重试卸载、查看详情 |

状态同步要求：

1. 插件广场安装验证通过后，快捷入口同步移除「新」。
2. 快捷入口安装验证通过后，插件广场同步显示基础可用及卸载操作。
3. 刷新或重新进入页面后，从真实状态恢复，不回退为默认未安装。
4. 同一使用范围内重复点击不重复安装；正在执行的任务可继续查看。
5. 已有可用配置直接复用，补齐插件登记与状态检查，避免重复安装；确认基础可用后记录首次安装已完成，移除「新」。
6. 持久化记录用户是否已完成首次安装及本次引导对应的版本，刷新、重新登录或更换客户端后保持一致。卸载不得清除首次安装完成记录。
7. 下次 Flocks 版本更新后，本次 REA 引导角标对仍未完成首次安装的用户失效；后续安装失败或状态变化也不恢复角标。
8. 移除角标不影响入口展示、安装权限或未安装时填入安装提示语（不自动发送）的行为。

**已确认角标规则：**显示条件为「用户未完成首次安装」且「本次版本引导期未结束」。首次安装完成以安装及所选档位可用性验证通过为准；卸载后重装不恢复，下次 Flocks 版本更新后未安装用户也不再显示。本次角标失效后，不因后续版本更新自动重新开启。

会话入口与插件广场读取、更新同一份插件安装状态，按统一状态决定安装、使用、修复和卸载操作。角标的用户首次安装记录与当前安装状态分别维护，卸载不清除首次安装完成记录。

## 5. 业务流程

### 5.1 首次通过快捷入口安装

1. 未安装用户点击 REA 入口；是否显示「新」按首次安装记录及版本引导期判定，不影响安装流程。
2. 将完整安装引导语填入 Rex 输入框，不创建已发送消息、不启动安装。用户可编辑，点击发送或按 Enter 后才发起安装；Shift+Enter 换行。
3. 检查已有技能、工具服务、基础依赖与 Flocks 配置。
4. 选择轻量档或完整档，复用已有组件，仅安装当前档位缺失的组件；可并行操作并行执行。执行系统软件包安装或平台配置写入前，先取得用户确认。
5. 遇到问题主动排查、修复，并重新验证。
6. MCP 服务仅注册一次，锁定 REA 6.4.0；验证服务启动、工具清单和真实工具调用。完整档须编译约 10 行 C 程序，依次调用 open_binary 与 procedure_pseudo_code，完成真实反编译验证。
7. 所选档位的可用性验证通过后更新状态、移除「新」，简明报告安装档位、已验证能力与未验证能力。轻量档须完成其支持能力的真实工具调用，不得标记原生反编译能力已验证。
8. 再询问分析文件、下载链接或网站 URL，以及希望解决的问题。
9. 根据目标检查并补齐专项工具，执行分析，尽可能在原程序或原运行环境中核对结果。
10. 输出分析结论、关键原理、证据、验证情况及未完成项。

安装阶段不得要求用户先提供分析材料或分析目标。基础验证不能用“进程已启动”或“安装命令成功”单独替代。

### 5.2 已安装后使用

1. 用户点击无「新」角标的 REA 入口，或插件广场中的「使用」。
2. 将「帮我使用 REA 逆向工具分析上传的附件文件」填入 Rex 输入框，不自动发送、不启动分析。
3. 用户可编辑引导语并上传附件，手动发送后开展分析；无附件时在会话中提示补充附件，不编造分析结果。需要明确分析重点时，再通过会话询问。
4. 复用已有配置，按目标检查工具与运行环境；异常时先排查和修复。
5. 补齐所需专项工具，开展分析与结果核对。
6. 输出可复核结论，区分已验证事实、推断和未完成项。

### 5.3 通过插件广场安装

1. 用户找到 REA 插件，点击「安装」。
2. 打开 Rex 输入界面并填入完整安装引导语，不自动发送。用户手动发送后创建或启动安装任务。
3. 按首次安装流程执行检查、配置、安装、故障处理和基础验证。
4. 插件广场同步进度和结果。
5. 基础验证通过后提供「使用」「卸载」，并同步移除快捷入口的「新」。

### 5.4 通过插件广场卸载

1. 用户点击「卸载」。
2. 展示卸载确认，说明即将停用 REA、清理插件专属资源，并保留共享依赖、历史会话、材料和报告。
3. 若有运行中相关任务，说明任务范围及停止影响，经用户确认后停止相关任务；确认任务已停止再继续卸载。用户未确认时不停止任务、不继续卸载。若无运行中相关任务，按卸载确认执行。插件广场和会话入口同步展示卸载进度。
4. 成功后更新为未安装；保留首次安装完成记录，快捷入口不恢复「新」。再次点击入口仍填入安装提示语（不自动发送）。
5. 失败时展示实际残留项和原因，提供重试，不提前报告卸载成功。

卸载资源边界与运行中任务规则：

- 仅清理插件专属资源，包括 REA 插件登记、专属技能、工具服务配置和专属组件。
- 保留共享依赖、历史会话、用户材料和已生成报告；不删除其他插件使用的服务和用户原有配置。
- 保留 /opt/ghidra_* 与 /root/.npm/_npx 缓存目录。
- 有运行中相关任务时，经用户确认停止相关任务后继续卸载；未确认时不停止任务、不执行卸载。
- 卸载成功须确认插件已停用、专属配置已清理、专属服务已停止或解绑，并报告保留的共享资源及缓存。

## 6. 会话提示语

### 6.1 首次安装提示语

```text
REA 安装指引
安装原则：仅安装缺失组件；凡可并行执行的操作一律并行，避免串行等待。

一、选择安装档位
轻量档——仅需 JavaScript / .NET / 压缩包分析时选用，不安装 JDK 与 Ghidra，可节省约 1.2GB 磁盘空间与约 4 分钟安装时间。
完整档——需反编译原生 ELF / PE 时选用，在轻量档基础上增装 JDK 21 与 Ghidra 12.1.4。
二、并行安装缺失组件（以下三项应同时执行）
技能组件：来源为 github:zouineoualid/rea-reverse-engineering/reverse-engineer-anything；该源存在间歇性不可达，安装失败时原样重试。
JDK 21：执行 dnf install -y java-21-openjdk-devel。
Ghidra 12.1.4：经 https://ghfast.top/ 镜像下载（官方直连速率约 30KB/s，预计耗时 4 小时）；下载后必须校验官方 SHA-256（ddac49f903da9d5bac833e5cc79395098b9c33cfd3279be5f31bd00387d2d4db），校验不通过须丢弃并重新下载；校验通过后解包至 /opt。
三、MCP 服务仅注册一次
服务名为 rea，启动命令为 npx -y rea-agents@6.4.0 --mcp（版本必须锁定 6.4.0）；写入环境变量 GHIDRA_INSTALL_DIR=/opt/ghidra_12.1.4_PUBLIC 与 JAVA_HOME=/usr/lib/jvm/java-21-openjdk。轻量档无需写入环境变量。
不得在安装前后各注册一次，以免产生额外的服务重连开销。

四、执行有效性验证
按所选安装档位执行真实验证，不得仅以服务启动成功或工具数量（170）作为可用性依据。
轻量档：不安装 JDK/Ghidra。使用本地生成或来源明确且附源码的最小 JavaScript 文件、.NET 托管程序集和 ZIP 压缩包进行真实工具调用验证，无需用户提供分析材料。JavaScript 和 .NET 样例均包含一个可核对的计算函数及固定输入输出，须通过实际工具还原逻辑，并尽可能在相应运行环境执行核对；ZIP 样例包含已知目录和文件，须通过实际工具列出、提取并核对内容。工具名称以真实 MCP 工具清单为准。逐项报告通过、失败与未完成，不将部分能力通过等同于全部能力可用。
完整档：先完成轻量档验证，再完成真实原生反编译验证。编译一个约 10 行、包含独立计算函数的 C 程序，依次调用 open_binary 与 procedure_pseudo_code，核对还原逻辑与源码一致，并运行原程序核对固定输入输出。仅确认工具数量（170）不足以证明原生反编译能力可用。

五、其他要求
组件已存在时应直接复用；/opt/ghidra_* 与 /root/.npm/_npx 为缓存目录，请勿删除——保留缓存可将重复安装耗时由约 6 分钟降至约 30 秒。
执行系统软件包安装或平台配置写入前，须先取得确认。
安装执行前请再次和我确认你计划安装哪些模块？
```

**档位执行规则（已确认）：**提示语中的 C 程序真实反编译验证仅作为完整档验收。轻量档不安装 JDK/Ghidra，执行其支持能力的真实工具调用验证；不得为完成 C 程序验证而将轻量档自动升级为完整档。并行安装仅针对所选档位中缺失且可并行的组件，轻量档不执行 JDK/Ghidra 安装。安装提示语与本条档位规则保持一致。

### 6.2 安装后使用提示语

```text
帮我使用 REA 逆向工具分析上传的附件文件
```

两种引导语仅预填到输入框，用户可编辑，不自动发送。点击入口不新增用户消息、不产生助手回复、不启动安装或分析任务。安装引导语下方不展示「REA 安装与基础验证」窗口；使用引导语下方不展示「将复用已有配置，并根据分析目标检查所需专项工具」说明及分析填写窗口。分析目标通过用户上传的附件提供。

## 7. 会话反馈与结果要求

### 7.1 安装反馈

会话展示检查、安装、配置、基础验证的阶段进度，并简明列出：

- 已复用与新安装的组件。
- Flocks 配置状态。
- 服务启动、工具清单、真实工具调用的各项结果及可查看的证据。
- 失败原因、修复结果和未完成项。
- 尚未验证的专项能力。
- 安装档位、REA 服务版本及单次注册情况。
- 完整档 Ghidra 下载文件的 SHA-256 校验结果和真实 C 程序反编译验证证据。
- 轻量档支持能力的真实工具调用记录、输入输出和验证结论；明确原生反编译未验证。

提示语中的容量、速度及安装耗时为用户提供的参考值，未在本文编写过程中实测，不作为固定性能承诺。

基础验证失败时，不进入正常分析引导，不记录首次安装完成。角标继续按首次安装记录及版本引导期判定：仍在引导期且从未完成首次安装时保留；已完成过首次安装或版本引导期已结束时不恢复。若需要权限或外部条件，应说明具体阻塞项和用户需完成的动作。

### 7.2 分析结果

结果至少包括：

| 内容 | 要求 |
| --- | --- |
| 简明结论 | 回答用户希望解决的问题 |
| 关键原理 | 说明还原的逻辑、算法或接口流程 |
| 可复核证据 | 给出文件位置、代码片段、调用记录、测试输入输出或其他实际获得的证据 |
| 验证情况 | 说明使用的程序、环境、方法和验证结果 |
| 推断 | 标明推断依据和限制 |
| 未完成项 | 说明未验证、无法执行或仍需补齐的部分 |

无法使用原程序或原运行环境核对时，明确原因和验证边界。没有实际工具调用或验证记录，不得声称对应能力已验证。

### 7.3 有效性验证样例与通过标准

验证样例由安装流程本地生成，或使用来源明确、附源码及校验值的固定测试样例，无需用户提供业务材料。先读取真实工具清单，再选择对应工具调用；不编造工具名或调用结果。

#### 7.3.1 轻量档

| 能力 | 最小样例要求 | 真实验证动作 | 通过标准 |
| --- | --- | --- | --- |
| JavaScript | 约 10～20 行独立 JS 文件，含 `calc(x) = x * 3 + 7`；固定输入 5，预期输出 22；无网络与第三方依赖 | 用 REA 实际工具读取或分析文件，获取计算逻辑；尽可能使用 JavaScript 运行环境执行核对 | 调用成功、还原逻辑与源码一致；运行成功时实际输出为 22 |
| .NET | 最小 C# 托管程序集，含 `Calc(int x)` 方法，逻辑为 `x * 3 + 7`；输入 5，预期输出 22；不引入第三方包 | 用 REA 实际工具打开并分析程序集，定位 Calc 并还原逻辑；尽可能在匹配的 .NET 环境执行核对 | 调用成功、还原方法逻辑与源码一致；运行成功时实际输出为 22 |
| 压缩包 | 无密码 ZIP，包含 `manifest.txt`、`docs/readme.txt`、`src/sample.js`；预先记录文件清单、内容和 SHA-256，JS 使用上述样例 | 用 REA 实际工具列出并提取到临时目录，核对清单、内容与 SHA-256 | 文件清单无漏项或多余项，内容与 SHA-256 均匹配 |

执行与判定要求：

- 三类验证可独立并行执行，分别记录结果。
- .NET 样例使用已有构建环境编译；无构建环境时可使用来源明确、附源码和校验值的测试程序集。
- 缺少运行环境、构建工具或专项工具时，优先复用已有资源；补齐时遵守安装确认规则，不为轻量档验证安装 JDK/Ghidra。
- 默认逐项验证 JavaScript、.NET、压缩包三类能力。真实工具分析通过但无法运行核对时，标记静态分析已验证、运行核对未完成；不能伪造输出。
- 三类真实工具分析均通过后，轻量档可按已验证能力确认基础可用；运行核对缺失须单独列出。若部分真实工具分析失败或未完成，报告部分可用，统一安装状态保留验证未完成或失败，不按全部通过移除首次安装角标。
- 不以轻量档通过宣称原生 ELF/PE 反编译可用。

#### 7.3.2 完整档

在轻量档验证基础上增加原生反编译样例：

1. 生成约 10 行 C 程序，包含独立计算函数 `calc(x) = x * 3 + 7` 和调用该函数的主程序。
2. 使用当前平台可用编译器生成原生可执行文件，保留计算函数便于定位；记录源码、编译参数、产物格式与 SHA-256。
3. 对产物真实调用 `open_binary`，再对计算函数调用 `procedure_pseudo_code`。
4. 核对伪代码计算语义与源码一致，不要求变量名称或文本完全相同。
5. 在原运行环境执行产物，固定输入 5 时输出须为 22，记录实际结果。
6. 工具调用、语义核对和程序执行均成功后，标记该样例对应格式与环境已验证；仅验证 ELF 不代表 PE 已验证，反之亦然。

缺少 C 编译器、调用失败或无法执行产物时，记录未完成项，不以工具数量或安装命令成功替代真实反编译验收。

#### 7.3.3 验证证据

逐项记录样例类型、源码或文件位置、校验值、真实工具名与调用参数、调用结果、预期结果、实际核对结果，以及通过/失败/未完成状态。报告分别汇总轻量能力与原生能力、静态分析与运行核对。

## 8. 异常与恢复

| 场景 | 处理要求 |
| --- | --- |
| 已有可用配置 | 复用并核对，避免重复安装 |
| 缺少基础依赖 | 自动补齐；需要权限时报告具体动作 |
| 服务启动失败 | 主动排查配置、依赖和启动错误，修复后重试 |
| 工具清单读取失败或真实调用失败 | 判定基础验证未通过，保留失败原因和证据 |
| 重复点击安装 | 复用当前任务与会话，不创建重复安装任务 |
| 用户离开页面 | 状态和任务可恢复查看，不以页面关闭判定成功或失败 |
| 分析目标所需工具缺失 | 根据目标补齐，再执行专项验证 |
| 安装后服务异常 | 优先修复已有配置，不默认重复完整安装 |
| 卸载部分失败 | 展示残留和真实状态，支持重试 |
| 目标不可访问或材料不完整 | 说明缺失项，询问补充材料，不编造分析结果 |

## 10. 已确认业务规则

1. 会话入口和插件广场安装使用统一状态，两处操作和展示保持同步。
2. 卸载仅清理插件专属资源，保留共享依赖、历史会话、材料和报告，以及安装指引要求保留的缓存。
3. 运行中相关任务经用户确认停止后继续卸载；用户未确认时不执行停止或卸载。
4. C 程序真实反编译验证仅作为完整档验收；轻量档执行其支持能力的真实工具调用。
5. 「新」仅在未完成首次安装且仍处于本次版本引导期时显示。首次安装完成后永久移除，卸载重装不恢复；一直未安装的用户下次 Flocks 版本更新后也去掉。

6. 安装和使用引导语只在输入框中预填，由用户手动发送后才启动对应任务。
7. 原型演示每次打开或刷新默认未安装，可手动切换已安装；此规则仅用于演示，真实产品仍读取统一安装状态，不因刷新重置。

8. 安装执行前，先向用户列明计划安装的模块（含拟补齐的依赖）、所选档位及已有复用项，再次取得用户确认后执行；将引导语发送到会话不等同于确认安装计划。
